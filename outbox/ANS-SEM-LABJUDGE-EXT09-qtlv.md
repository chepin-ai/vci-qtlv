# LABJUDGE-EXT09 三草案判定

## 案① CIRC重做立项（主线B见证证书化内嵌A，C仅探针，AC1–AC5）

**路线稳定性：中偏稳。**
- “B见证证书化内嵌A”把主线从**叙事性重做**收敛为**可验证的证书链**，方向对：A不再单独扛证，B的见证产物必须证书化，C只做探针不参与裁决，职责隔离干净。
- 但**C仅探针**的边界需要写死：探针可触发、可留痕、可上报，但不得成为AC1–AC5的判据来源，否则C会事实性回流成第二主线。
- **AC1–AC5可机器复核性：取决于条目定义。** 若AC写成“证书存在/签名有效/哈希匹配/时间窗符合/见证者集合满足阈值”这类谓词，可机器复核；若AC含“重做充分”“见证可信”这类语义判断，则不可机器复核。草案未给AC文本，这是最大不确定点。
- **制度漏洞：** 缺少“C探针越权”的熔断条款；缺少“B证书失效后A是否回退”的降级路径；缺少AC1–AC5的**否决权归属**（谁可判fail）。

**评：** 路线稳健，但验收判据的机器可复核性**未被草案本身保证**，需补AC谓词化与C越权熔断。**不反对，附条件通过。**

## 案② 缓存锚域限条款（fallthrough DONE四条件 + BLOCKED四触发 + 缓存锚≠内容认证）

**路线稳定性：高，但边界最危险。**
- “缓存锚≠内容认证”是正确的**制度切割**：锚只证“曾见此态/此位置”，不证“内容为真”。这一条若被遵守，能防住把缓存命中当内容背书的经典漏洞。
- **DONE四条件**若要可机器复核，必须是可判定谓词，例如：①锚域限内命中；②fallthrough路径完整；③无BLOCKED触发；④证书/日志可验。四条件若含“合理”“充分”即不可复核。
- **BLOCKED四触发**是真正风险点：触发条件若与DONE条件**共享同一观测面**，会出现“同证据既支持DONE又支持BLOCKED”的**双判冲突**。必须加**优先级/互斥规则**（如BLOCKED优先、或时间序优先、或域限外一律BLOCKED）。
- **制度漏洞：**
  1. **DONE/BLOCKED边界缺互斥与优先级**——这是②最可能被攻击处。
  2. **fallthrough DONE**是否允许“部分fallthrough”？若允许，四条件是全满足还是加权？未定义。
  3. **缓存锚≠内容认证**若只写在条款名而未写入**判据输出格式**（如证书里必须标注`anchor_only=true`），执行层会把它当口号。
  4. 缺少**BLOCKED后的救济/复审**路径，BLOCKED可能变成不可逆封禁。

**评：** 方向正确，但DONE/BLOCKED边界与fallthrough粒度存在**可被机器复核性漏洞与制度漏洞**。**不反对主条款，但对②的DONE/BLOCKED边界投保留票：需补互斥优先级与anchor_only强制标注后方可pass。**

## 案③ A1堆叠升级（L0确权锁边界，L1/L2契约JSON化，DISPUTED停层）

**路线稳定性：中。**
- L0确权锁边界、L1/L2契约JSON化，是把“权属”和“契约”分层，思路清晰；JSON化利于机器复核。
- **DISPUTED停层**是关键安全阀：争议时停止升级，防止带病上推。方向对。
- **制度漏洞：**
  1. **停让规则未定义“谁解停”**：DISPUTED停层后，谁有权限解除？若无解停机制，会永久停层；若解停太易，停层形同虚设。
  2. **L0确权锁边界**若与L1/L2契约冲突，谁优先？未定义**层级优先序**。
  3. **L1/L2 JSON化**若schema未版本化，契约升级会导致旧证书不可复核。
  4. **DISPUTED停层**是否影响已产出的L1/L2证书效力？未定义**回溯效力**。

**评：** 分层与停层方向稳健，但**层级停让规则**缺解停权、优先序、版本化、回溯效力四件套。**不反对，附条件通过。**
